# Mobile audit B: Cockpit, Context, CCTV, Radio

Read-only audit. No source was edited. Scope: `src/ui/templates/cockpit.html`, `context.html`, the CCTV and Radio markup (which lives in `layer-panels.html` and `scene-chrome.html`, not in a cctv/radio template), `src/ui/styles/{cockpit,cctv,radio}.css`, `src/ui/{cockpit*,context*,cctv*,radio*}.js`, `src/cockpit*.js`, `src/cctvFocus*.js`, `src/contextModePolicy.js`, plus their tests. Line numbers are as of commit 5d6b944.

Legend for "Mobile treatment": **STAY** = remains on screen as a HUD/primary control; **MENU:x** = belongs in section x of the new mobile menu; **SHEET** = full-screen (or bottom) sheet.

---

## 0. Headline findings (read these first)

1. **On <=760px, cockpit mode currently HIDES most of its own UI.** `cockpit.css:2016-2196` applies `display:none !important` to `.cockpit-context-window` (Contact panel), `.cockpit-signal-window` (Briefing carousel AND the Estimated Flight Plan card, which is nested inside it), `#left-panel-stack`, `#intel-hud`, `#right-context-rail`. On a phone the user therefore cannot reach: contact prev/next, cohort counts, WX (weather effects) toggle, briefing pages (signals / news / local), the route card, or Radio/Display "full" panels. Only vision cycler, instruments, Display/Radio utility launchers and EXIT/RESET remain. `cockpitLayout.js` still computes `compact-bottom` / `compact-top` layout modes for those panels (lines 79, 100) but they are dead code on mobile because CSS hides them. A mobile rewrite must decide where these live (recommended: a cockpit sheet).
2. **Exit is button-only on touch.** ESC / `C` are keyboard shortcuts (`cockpitInput.js`); the `.cockpit-help` text "ESC EXIT · C TOGGLE" (`cockpit.html:272`, `cockpit.css:1924`) is still shown on phones and is wrong for touch.
3. **Font sizes are 5-9 px** on almost every cockpit control (`.cockpit-vision-controls` 6-9px, `.cockpit-brief-actions` 6px, `.cockpit-context-footer` 5px in mobile media, brief tabs 6px, `#view-switcher` 7px in mobile). Tap targets are 20-31 px high (`.cockpit-utility-glyph` 20x20, `.cockpit-brief-actions button` 23x24, `.cockpit-context-actions button` 28x24, `.cockpit-context-weather` 20px tall, brief tabs about 14px tall, `.cctv-cal-value` about 20px).
4. **3D perspective transforms on interactive panels** (`rotateY(4deg) translateZ(18px)` on context/signal windows; `rotateY(±7deg)` on speed/altitude readouts; `#cockpit-hud { perspective: 920px }`). Hit-testing and text crispness suffer on touch; `#cockpit-hud` also becomes a containing block for `position:fixed` descendants, so the mobile `position: fixed` on `.cockpit-utility-control.is-expanded` resolves against the HUD (fixed inset:0, so equivalent today, but do not rely on it).
5. **Hover dependency:** briefing auto-rotate pauses on `:hover` (`cockpitBriefing.js:78`); CCTV hover-card on globe camera icons is MOUSE_MOVE-driven (`src/layers/cctv/hover.js`); `title=` tooltips carry information (brief cycle help text, Contact prev/next explanations, TR-3B). There is no `hover:none` / `pointer:coarse` branch anywhere in this slice.
6. **Drag-only / precision gestures:** Radio tuner (`#radio-tuner-slider`, pointer capture + custom drag model, `touch-action:none`, thumb 14x47) and CCTV ADJUST mode (in-world gizmo drag: rings rotate, arrows move, handles set range/FOV) plus two volume sliders. The tuner is already pointer-event based (touch works) but its scrub width is the panel width (about 300px) with a "snaps to available stations" model.
7. **Two DOM owners for Radio controls in cockpit vs. context, and Display controls are MOVED (portalled) into the cockpit panel** at runtime. Re-parenting rules in section 5 are critical.
8. **One `@media (max-width: 760px)` block in cockpit.css is pinned by test text** (section 7). Any mobile addition must not be inserted between that block and the following `@media (prefers-reduced-motion` block, and should not change the 760px block content the tests assert.

## 10. Risks / open questions for the rewrite

- Decide whether Contact/Briefing/Route information should return to mobile cockpit at all (currently CSS-deleted); if so, retire the dead `compact-bottom`/`compact-top` branches or make them real, and update the pinned 760px test.
- 760px (cockpit) vs 720px (`responsive.css`) thresholds differ: a phone landscape at 740-760px gets cockpit-mobile but desktop-ish everything else. Pick one breakpoint or a pointer-based query.
- `vh` used for max-heights (`calc(100vh - 260px)`, `min(52vh,470px)`); mobile browser chrome will clip. Move to `dvh`/`svh` in new code.
- Radio state is mirrored in three DOM surfaces via `radioPresentation.js`; a fourth surface should be avoided (reuse the embedded `#radio-*` nodes in a sheet).
- `_revealRadio*` scroll helpers and `panel-collapse-btn` semantics assume the nested desktop scroller.
- Auto-rotate "pause on hover/focus" has no touch equivalent; define "user interacting" (touchstart within window / sheet open).
- Weather effects toggle (WX) is only reachable through the Contact window; it must get a mobile home.
- Focus management on enter (`map-view-switch.focus()`) and on exit (`entry.focus()`) is keyboard-oriented; harmless on touch but may pop virtual UI on some browsers (buttons only, low risk).
- CCTV ADJUST gizmo and the hover card are in `src/layers/cctv` (not this slice) and are mouse-driven; need a separate touch assessment.
